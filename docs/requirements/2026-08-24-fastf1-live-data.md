# FastF1 实时数据层（f1db 权威 + FastF1  provisional）

日期：2026-08-24
状态：待定（设计已讨论，未排期实现）

## 背景与目标

f1db 是权威但慢的源：主版本集中在周日晚 UTC 发布（赛后数小时），修正版散落工作日。比赛周末进行中（周六排位、周日正赛刚结束）f1db 没有新数据，站点在此期间没有新鲜内容。FastF1 能在会话结束后几分钟内拿到结果与遥测，填上这个窗口。目标：静态/历史全走 f1db，周末实时走 FastF1，两者自动交接。

## 用户可见行为

- 比赛周末：会话结束后短时间内站点出现该会话结果，标记为"provisional · live timing"。
- f1db 主版本到达后（通常周日晚至周二），同一内容切换为权威数据，provisional 标记消失；数值若有出入以 f1db 为准。
- 后续阶段（不在本需求）：圈速/遥测可视化（lap 图表、差距分析）基于 FastF1 遥测。

## 设计结论

- 单一读路径：FastF1 数据不进第二套表，直接补写进 D1 同一批表。同步流水线每次运行 = [f1db 全量导入] + [FastF1 补齐 f1db 缺失的会话]，顺序固定（全量导入会清库，补齐必须在其后同次运行内执行，否则周末 provisional 数据会被清掉）。
- 交接无需显式"替换事件"：补齐逻辑对 f1db 已含的会话跳过（f1db 优先），f1db 追上后 FastF1 的 provisional 行自然被权威导入覆盖/跳过。
- 来源标记：按会话记录 source（f1db | fastf1）与 fetched_at，供 UI 显示 provisional 徽章（复用 freshness 语义）。
- FastF1 礼仪与成本：比赛周末每 30-60 分钟轮询会话状态；每个完成的会话只拉取一次并缓存；非周末不跑（f1db 轮询覆盖）。
- 运行环境：FastF1 是 Python 且重，跑在 GitHub Actions（Workers 跑不了）；`scripts/generate-circuit-maps.py` 已有 fastf1 依赖先例。
- 授权前提：FastF1 抓取官方 timing 的非公开端点，非商业/研究用途社区默认容忍；本站为非商业粉丝站，维持该前提并记录；若用于商业需另行许可审查。

## 验收标准（实现时）

- 周末会话结束后 ≤1h 站点可见 provisional 结果；f1db 主版本同步后 provisional 标记消失且数据与 f1db 一致。
- 全量导入 + 补齐在同一次工作流运行内原子完成；补齐失败不影响 f1db 数据可用性。
- FastF1 对上游的请求频率符合上述礼仪；每会话单次拉取有缓存证据（测试或日志）。
